# Huawei B612s-25d Dropbear SSH

A static Dropbear SSH server for the Huawei B612s-25d router.

This project targets the Huawei B612s-25d firmware environment and installs a statically linked ARMv7 Dropbear server using ADB root access.

## Target device

Tested against:

```text
Device        : Huawei B612s-25d
Hardware      : WL1B612M01
Android       : 4.4.1
Kernel        : Linux 3.10.59+ armv7l
Software      : 81.201.01.01.234
Web UI        : 81.100.35.02.234
```

The installer is designed around the following firmware characteristics:

```text
/system                    YAFFS2, normally read-only after boot
/data                      YAFFS2, read-write
/system/etc/init.d/        Not present
/init.rc                   Imports /init.huawei.rc
/init.huawei.rc            Starts /system/etc/autorun.sh
```

The persistent startup mechanism therefore uses the existing Huawei:

```text
/system/etc/autorun.sh
```

No modification of `/init.rc` or `/init.huawei.rc` is required.

## Features

- Dropbear SSH server
- Static ARMv7-A binary
- VFPv3-D16
- softfp floating-point ABI
- RSA host key
- ECDSA host key
- Ed25519 host key
- Public-key authentication
- Explicit `authorized_keys` directory
- Automatic root-home detection from `/etc/passwd`
- Persistent startup after reboot
- Waits for the router LAN interface before binding
- Safe repeated installer execution
- Original Huawei `autorun.sh` preserved
- Windows `.bat` installer
- Linux/macOS Bash installer
- Weekly upstream Dropbear version detection
- Automatic GitHub Release creation for new upstream versions

## ⚠️ Password Authentication Notice

### Password login is not supported on this Huawei B612 firmware

On the Huawei B612s-25d firmware tested with this project, SSH password authentication does not work reliably because of the way the Huawei/Android-based system handles the root password database.

The device contains:

```text
/system/etc/passwd
```

with the root account represented as:

```text
root::0:0:root:/data/root-home:/bin/sh
```

There is also no usable:

```text
/etc/shadow
```

file on the tested firmware.

Although the built-in BusyBox `passwd` command accepts a password change, the password hash is not persisted in a form that Dropbear can use for SSH password authentication. Consequently, Dropbear rejects password authentication even when the password appears to have been successfully changed locally.

This is a limitation of the Huawei firmware's account/password implementation, not a networking or SSH connectivity problem.

### Use SSH public-key authentication instead

This project is therefore designed to use SSH public-key authentication.

Place your public key in:

```text
/data/root-home/.ssh/authorized_keys
```

The corresponding private key remains on your computer.

For example:

```sh
ssh -i ~/.ssh/your_private_key root@192.168.0.217
```

Do **not** rely on the router's `passwd` command to enable SSH password login.

Dropbear officially supports RSA, Ed25519, and ECDSA keys through `authorized_keys`.

## Releases

Release packages are automatically built from the upstream Dropbear release.

The release package contains:

```text
DROPBEAR_<version>_armv7_soft-float_static_B612-25d.zip
├── dropbear
├── dropbearkey
├── install-dropbear.sh
├── install-dropbear.bat
└── BUILD-INFO.txt
```

The upstream Dropbear version is checked weekly by GitHub Actions.

When a new upstream `DROPBEAR_*` release is detected, the workflow:

1. Downloads the upstream source tarball.
2. Cross-compiles Dropbear for ARMv7-A.
3. Uses VFPv3-D16 and the softfp ABI.
4. Builds statically.
5. Verifies the resulting ELF files.
6. Verifies the Dropbear version.
7. Packages the server and installer files.
8. Creates a GitHub Release automatically.

A manual workflow dispatch is also available.

The workflow requires `contents: write` permission so GitHub Actions can create releases.

## Current build target

The binaries are built with:

```text
-march=armv7-a
-mfpu=vfpv3-d16
-mfloat-abi=softfp
-static
```

The resulting executables are intended for the B612s-25d ARMv7 environment.

## Windows installation

Default router address:

```cmd
install-dropbear.bat
```

Explicit router IP:

```cmd
install-dropbear.bat 192.168.8.1
```

Explicit ADB endpoint:

```cmd
install-dropbear.bat 192.168.8.1:5555
```

The installer:

1. Checks the local Dropbear binaries.
2. Connects to ADB.
3. Requests root ADB.
4. Verifies the ARMv7 device.
5. Reads the root entry from `/etc/passwd`.
6. Determines the root home directory.
7. Remounts `/system` read-write.
8. Creates the Dropbear directories.
9. Installs `dropbear` and `dropbearkey`.
10. Generates persistent host keys.
11. Generates `/system/bin/dropbear-start`.
12. Installs the persistent `autorun.sh` hook.
13. Verifies the installation.

The installer does not start Dropbear immediately.

Reboot the router after the installer completes.

## SSH public-key authentication

The installer reads the root account from:

```text
/etc/passwd
```

The passwd format is:

```text
name:password:UID:GID:GECOS:directory:shell
```

The sixth field is used as the root home directory.

For example:

```text
root::0:0:root:/data/root-home:/bin/sh
```

results in:

```text
ROOT_HOME=/data/root-home
ROOT_SSH_DIR=/data/root-home/.ssh
```

Therefore the expected public-key file is:

```text
/data/root-home/.ssh/authorized_keys
```

Do not assume that `/data/.ssh/authorized_keys` is the correct location.

The installer explicitly starts Dropbear with:

```text
-D /data/root-home/.ssh
```

or the equivalent directory detected from `/etc/passwd`.

## Installing your public key

After installation, create:

```text
/data/root-home/.ssh/authorized_keys
```

with permissions:

```text
0700  /data/root-home/.ssh
0600  /data/root-home/.ssh/authorized_keys
```

and ownership:

```text
root:root
```

For example, from a root ADB shell:

```sh
mkdir -p /data/root-home/.ssh
chmod 0700 /data/root-home/.ssh
chown root:root /data/root-home/.ssh
```

Then install your public key:

```sh
cat /tmp/your-public-key >> /data/root-home/.ssh/authorized_keys
```

Finally:

```sh
chown root:root /data/root-home/.ssh/authorized_keys
chmod 0600 /data/root-home/.ssh/authorized_keys
```

A typical public key looks like:

```text
ssh-rsa AAAAB3... user@computer
```

The comment at the end of the key is optional.

## SSH connection

After reboot:

```bash
ssh root@192.168.8.1
```

If the router is using another LAN address:

```bash
ssh root@<router-ip>
```

Port 22 is used by default.

For a specific private key:

```bash
ssh -i /path/to/private-key root@192.168.8.1
```

For verbose authentication debugging:

```bash
ssh -vvv -o IdentitiesOnly=yes -i /path/to/private-key root@192.168.8.1
```

## Persistent startup

The installer does not modify:

```text
/init.rc
```

or:

```text
/init.huawei.rc
```

Instead, it uses Huawei's existing:

```text
/system/etc/autorun.sh
```

The installer creates:

```text
/system/bin/dropbear-start
```

and appends a small hook to `autorun.sh`:

```sh
/system/bin/dropbear-start >/dev/null 2>&1 &
```

The launcher waits until:

```text
br0
```

has the configured router LAN address.

This avoids starting Dropbear before the LAN interface is ready.

The launcher then starts Dropbear in normal daemon mode.

## Dropbear command line

The persistent launcher effectively starts:

```sh
/system/bin/dropbear \
    -E \
    -D "$ROOT_SSH_DIR" \
    -r /system/etc/dropbear/dropbear_rsa_host_key \
    -r /system/etc/dropbear/dropbear_ecdsa_host_key \
    -r /system/etc/dropbear/dropbear_ed25519_host_key \
    -p "$IP:$PORT"
```

The launcher deliberately does not use `-F`, allowing Dropbear to daemonize normally.

`-E` keeps logging directed to stderr rather than a separate log file.

## Host keys

Host keys are stored under:

```text
/system/etc/dropbear/
```

The installer generates:

```text
dropbear_rsa_host_key
dropbear_ecdsa_host_key
dropbear_ed25519_host_key
```

Private host keys are protected with:

```text
0600
```

and owned by:

```text
root:root
```

Existing host keys are preserved on subsequent installer runs.

This means an existing SSH client's known-host identity normally remains stable across router reboots and repeated installer executions.

## Re-running the installer

The installer is designed to be repeatable.

On the first installation it creates:

```text
/system/etc/autorun.sh.dropbear.orig
```

This is a pristine backup of the original Huawei `autorun.sh`.

On later runs, the installer:

1. Restores `autorun.sh` from the pristine backup.
2. Appends exactly one Dropbear startup block.
3. Reinstalls the launcher.
4. Preserves existing host keys.
5. Preserves an existing `authorized_keys` file.

This prevents repeated installer executions from accumulating multiple Dropbear startup blocks.

## Important: installer does not start Dropbear

The installer intentionally does not start the SSH server.

At the end you will see a message telling you to reboot.

After reboot, Huawei's normal boot process starts:

```text
autorun.sh
    |
    +-- dropbear-start
             |
             +-- waits for br0
             |
             +-- starts Dropbear
```

## Verifying after reboot

Use ADB:

```bash
adb connect 192.168.8.1:5555
adb root
adb shell
```

Check the launcher:

```sh
ls -l /system/bin/dropbear-start
```

Check Dropbear:

```sh
ps | grep '[d]ropbear'
```

Check port 22:

```sh
busyboxx netstat -tunlp | grep ':22'
```

Check the authorization directory:

```sh
ls -ld /data/root-home/.ssh
ls -l /data/root-home/.ssh/authorized_keys
```

Check the persistent hook:

```sh
grep -n -A12 -B2 'DROPBEAR SSH SERVER' /system/etc/autorun.sh
```

## Debugging public-key authentication

If SSH connects but rejects the public key, run Dropbear manually in foreground debug mode.

First stop the existing Dropbear process.

Then:

```sh
/system/bin/dropbear -F -E \
    -D /data/root-home/.ssh \
    -r /system/etc/dropbear/dropbear_rsa_host_key \
    -r /system/etc/dropbear/dropbear_ecdsa_host_key \
    -r /system/etc/dropbear/dropbear_ed25519_host_key \
    -p 192.168.8.1:22
```

From the client:

```bash
ssh -vvv \
    -o IdentitiesOnly=yes \
    -i /path/to/private-key \
    root@192.168.8.1
```

The Dropbear terminal should show authentication-related diagnostics.

Check:

```sh
ls -ld /data/root-home
ls -ld /data/root-home/.ssh
ls -l /data/root-home/.ssh/authorized_keys
```

The `.ssh` directory and `authorized_keys` should not be writable by other users.

## Files installed on the router

The installer installs:

```text
/system/bin/dropbear
/system/bin/dropbearkey
/system/bin/dropbear-start

/system/etc/dropbear/dropbear_rsa_host_key

```

The user's public key is stored according to the root home directory in `/etc/passwd`.

## What is not installed

The installer does not install:

```text
/etc/init.d/
/system/etc/init/dropbear.rc
```

and does not modify:

```text
/init.rc
/init.huawei.rc
```

The persistent startup mechanism is specifically based on the existing Huawei `autorun.sh` service.

## Security considerations

This project enables a root SSH server on the router.

That provides full administrative access to the device.

Use public-key authentication and keep the private SSH key secure.

Do not expose TCP port 22 directly to the Internet unless you understand and intentionally accept the associated security risks.

The router is an old Android/Linux platform, so it should not be treated as a modern, fully supported security appliance.

## Uninstallation / rollback

The original Huawei boot script is preserved as:

```text
/system/etc/autorun.sh.dropbear.orig
```

To remove the persistent Dropbear startup hook manually:

```sh
cp /system/etc/autorun.sh.dropbear.orig /system/etc/autorun.sh
chmod 0700 /system/etc/autorun.sh
chown root:root /system/etc/autorun.sh
```

Then reboot.

To remove the installed binaries:

```sh
rm -f /system/bin/dropbear
rm -f /system/bin/dropbearkey
rm -f /system/bin/dropbear-start
```

To remove Dropbear host keys:

```sh
rm -rf /system/etc/dropbear
```

Do not remove the user's `.ssh` directory unless you also intend to remove the authorized keys.

```text

     |
     v

     |
     v

     |
     v

     |
     v
```


